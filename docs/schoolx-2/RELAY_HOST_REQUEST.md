# 테스트 서버 확인 요청

빌려주기로 한 컴퓨터에 중계 서버를 올리려고 합니다. 준비하려면 몇 가지를
알아야 해서 정리했습니다. 마지막 답변 양식만 채워서 보내주세요.

- **기간**: [채울 곳 — 예: 3~4주]
- **인원**: [채울 곳 — 예: 5명]
- **끝나면**: 정식 서버로 옮기고 그 컴퓨터에 설치한 건 전부 지웁니다
  (`docker compose down -v` 한 줄)

---

## 1. 올라가는 것

Docker 컨테이너 네 개. 전부 컨테이너 안에서만 돌고 기존 환경은 안 건드립니다.

| 이름 | 역할 |
|---|---|
| relay | 앱이 접속하는 중계 서버 |
| postgres | 메시지 저장 |
| redis | 실시간 전달 |
| minio | 첨부파일 저장 |

디스크 20GB, 메모리 4GB 정도 씁니다. 포트는 80·443을 쓰는데 아래 2-B 답에 따라
달라집니다.

---

## 2. 알아둘 것 두 가지

**중계 서버를 가진 쪽은 오가는 메시지를 다 볼 수 있습니다.** DB에 본문이 그대로
저장돼서 그렇고, 설정으로 막을 수 있는 게 아니라 구조가 그렇습니다. 그래서 이번
테스트에는 실제 학생 이야기나 민감한 대화는 안 넣습니다. 설치랑 첫 접속이 되는지만
봅니다.

**서버가 꺼지면 전원이 멈춥니다.** 절전에 들어가거나 재부팅 중에는 아무도 앱을 못
씁니다. 그래서 아래에서 상시 가동 여부를 묻습니다.

---

## 3. 알려줄 것

### A. 기계

터미널에 붙여넣고 결과를 그대로 보내주세요. **오류가 나면 그 오류 메시지도 그대로**
보내주시면 됩니다 — 그것도 답이 됩니다.

**macOS** — 터미널

```bash
sw_vers; uname -m; df -h / | tail -1; docker --version 2>/dev/null || echo "docker: 없음"
```

**Linux** — 터미널

```bash
head -2 /etc/os-release; uname -m; free -h | head -2; df -h / | tail -1; docker --version 2>/dev/null || echo "docker: 없음"
```

**Windows** — PowerShell (시작 메뉴에서 "PowerShell" 검색)

```powershell
Get-ComputerInfo | Select-Object WindowsProductName,WindowsVersion,OsArchitecture,CsTotalPhysicalMemory | Format-List
"CPU: $env:PROCESSOR_ARCHITECTURE"
"C드라이브 여유: {0:N0} GB" -f ((Get-PSDrive C).Free / 1GB)
wsl --status
docker --version
```

노트북인지 데스크톱인지, 들고 다니는지도 같이 알려주세요.

### B. 네트워크 — 여기서 길이 갈립니다

1. 공인 IP가 있습니까, 공유기 안쪽입니까?
   - 모르겠으면 [ifconfig.me](https://ifconfig.me) 주소와 내부 IP를 같이
     보내주세요
     (macOS: `ipconfig getifaddr en0` / Linux: `hostname -I` /
     Windows PowerShell: `ipconfig | findstr IPv4`).
     둘이 같으면 공인 IP입니다
2. 80·443 포트를 밖에서 들어오게 열 수 있습니까?
3. 공유기 관리자 페이지에 들어갈 수 있습니까?

### C. 도메인

1. 서브도메인 하나 줄 수 있습니까? (예: `relay.<도메인>`)
   - https 인증서 때문에 IP만으로는 안 되고 도메인이 필요합니다
2. 그 도메인 DNS를 어디서 관리합니까? (가비아 / 후이즈 / Cloudflare / Route 53 / 기타)

### D. 운영

1. 테스트 기간 24시간 켜 둘 수 있습니까? 전원은 항상 연결돼 있습니까?
2. 절전·최대절전 꺼도 됩니까? (노트북이면 덮개 닫아도 안 자야 합니다)
3. 재부팅·업데이트 후 자동 시작되게 해도 됩니까?
4. 관리자 권한 있습니까? (macOS·Linux는 `sudo`, Windows는 관리자 계정)
5. 원격 접속으로 제가 설정해도 됩니까?
   - 열어주면 30분이면 끝납니다. 직접 하면 명령 주고받느라 며칠 걸립니다
   - macOS·Linux는 SSH, Windows는 OpenSSH 서버나 화면 공유(팀뷰어 등)

### E. Windows인 경우만 — 추가로

Windows는 서버로 쓸 때 걸리는 게 몇 개 더 있습니다.

1. **Docker Desktop + WSL2를 설치해도 됩니까?**
   - Windows에서 Docker를 돌리려면 WSL2(윈도우 안의 리눅스)가 필요합니다.
     설치는 자동이지만 재부팅이 한 번 필요하고, BIOS에서 가상화가 꺼져 있으면
     그것도 켜야 합니다
2. **자동 로그인을 설정해도 됩니까?** — 이게 Windows에서 제일 중요합니다
   - Docker Desktop은 **사용자가 로그인해야** 뜹니다. 자동 로그인이 없으면
     재부팅 후 아무도 로그인하지 않는 동안 서버가 계속 죽어 있습니다.
     macOS·Linux에는 없는 문제입니다
   - 자동 로그인이 부담되면(개인 파일이 있는 계정이면 그럴 수 있습니다)
     서버 전용 계정을 하나 만드는 방법도 있습니다
3. **Windows Update 자동 재부팅을 미뤄도 됩니까?**
   - 기본 설정이면 업데이트가 알아서 재부팅합니다. 활성 시간을 조정하거나
     자동 재부팅을 꺼야 합니다
4. **빠른 시작(Fast Startup)을 꺼도 됩니까?**
   - 켜져 있으면 종료가 완전한 종료가 아니라서 Docker가 이상하게 복구됩니다
5. **Windows 버전이 무엇입니까?** — 위 A의 명령 결과로 확인됩니다
   - Windows 11이나 Windows 10 (빌드 19044 이상)이어야 WSL2가 돌아갑니다.
     Home 에디션도 됩니다

> **참고**: Windows도 되긴 하지만 준비에 1~2시간이 더 들고, 위의 자동 로그인
> 문제 때문에 상시 가동 신뢰도가 한 단계 떨어집니다. 혹시 쓸 수 있는
> Mac이나 Linux 기계가 따로 있으면 그쪽이 낫습니다.

## 5. 이후 진행

| 순서 | 하는 일 | 누가 |
|---|---|---|
| 1 | 그 기계에 맞는 이미지 준비 | 우리 |
| 2 | DNS에 레코드 하나 추가 | 그쪽 (또는 알려주면 우리가) |
| 3 | 컨테이너 설치·실행 | 우리 (원격 허용 시) |
| 4 | 인증서 자동 발급 확인 | 우리 |
| 5 | 앱 접속 확인 | 우리 |

**B 답에 따라**

- **공인 IP + 포트 개방 가능** — A 레코드 하나 걸면 끝. 인증서는 자동 발급됩니다.
  가장 간단합니다
- **공유기 안쪽** — 포트를 안 열고 우회하는 방법(Cloudflare Tunnel)을 씁니다.
  대신 도메인 네임서버를 Cloudflare로 옮겨야 해서, 그 도메인을 다른 데도 쓰고
  있으면 부담이 됩니다. 이 경우 먼저 상의합시다

**Windows면 1번 앞에 세 단계가 더 붙습니다**

| 순서 | 하는 일 | 누가 |
|---|---|---|
| 0-1 | WSL2 설치 (재부팅 1회, BIOS 가상화 확인) | 그쪽 또는 원격으로 우리가 |
| 0-2 | Docker Desktop 설치 + WSL2 연동 | 〃 |
| 0-3 | 자동 로그인 · 절전 · 빠른 시작 설정 | 〃 |

이후 작업은 WSL2 안의 리눅스에서 하므로 Mac·Linux와 같아집니다.
