# SchoolX 2.0 구현 세션 운영

이 문서는 SchoolX 2.0을 여러 세션과 추론 수준으로 개발할 때 품질을 유지하기 위한 작업 경계를 정의한다.

## 기본 원칙

- 구조, 권한, 프로토콜, 배포 설정을 바꾸는 작업은 GPT-5.6-sol의 매우 높은 추론으로 수행한다.
- 이미 확정된 패턴을 여러 파일에 반복 적용하는 작업은 낮은 추론으로 전환할 수 있다.
- 낮은 추론 작업은 파일 범위, 변경 금지 사항, 완료 조건, 실행할 검증 명령이 모두 정해진 경우에만 시작한다.
- 각 세션은 하나의 구조적 관심사만 다루고, 통과한 테스트와 남은 위험을 문서에 남긴다.
- 낮은 추론 모델의 결과는 구조를 정한 고추론 세션에서 통합 검토한다.

## 현재 구현 상태

브랜치: `codex/schoolx-2-foundation`

완료:

- 원본 Buzz 데스크톱 기준선 확인
- 한국어·영어 번역 런타임
- 저장된 언어 우선 적용
- 선택 이력이 없는 새 설치의 한국어 기본값과 영어 폴백
- HTML `lang` 동기화
- 설정 화면에서 즉시 언어 전환
- 앱 로딩 상태와 설정 화면 첫 번역
- 한국어 시스템 글꼴 폴백
- 로케일 판별·저장과 번역 키 일치 단위 테스트
- 언어 전환과 새로고침 후 유지 E2E 테스트
- 타입 검사, 정적 검사, 프로덕션 빌드, 전체 단위 테스트 통과

다음 구현 작업:

- 제품 설정 계층과 SchoolX 브랜딩 분리 설계
- 이후 화면별 한국어 문자열을 기능 단위로 점진 추출

## 모델을 낮춰도 되는 작업

다음 작업은 현재 다국어 API와 UI 패턴이 변경되지 않는 조건에서 낮은 추론 모델로 수행할 수 있다.

### 화면 문자열 추출

- 지정된 기능 디렉터리의 사용자 노출 영어 문구 추출
- 기존 번역 카탈로그에 키 추가
- `useTranslation()`과 `t()` 적용
- 비즈니스 로직, 테스트 ID, 프로토콜 값은 변경하지 않음

권장 작업 단위:

- 온보딩 화면
- 채널 목록과 채널 생성
- 메시지 작성기와 스레드
- 검색
- 에이전트 목록
- 캔버스와 포럼
- Huddle
- 알림과 업데이트

한 번에 한 기능 디렉터리만 맡긴다.

### 번역 카탈로그 품질 작업

- 한국어 문체 통일
- 영어·한국어 키 구조 일치 검사
- 누락된 키에 대한 테스트 추가
- 버튼 폭과 줄바꿈 같은 단순 UI 보정

### 템플릿 콘텐츠

템플릿 스키마와 적용 API가 고추론 세션에서 확정된 뒤 다음 작업을 낮은 추론으로 전환할 수 있다.

- 업무방 10개의 이름과 설명
- 시작 캔버스 콘텐츠
- 페르소나 설명
- 운영 규칙과 예제 워크플로
- 템플릿 데이터 스냅샷 테스트

## GPT-5.6-sol의 매우 높은 추론을 유지할 작업

- 제품 설정 계층과 Buzz/SchoolX 브랜딩 분리
- Tauri 앱 식별자, 딥링크, 데이터 디렉터리, 업데이트 경로
- 채널 템플릿의 재적용 및 중복 방지 설계
- 관리형 에이전트 생성과 재사용 규칙
- 코디네이터의 채널 권한과 비공개 정보 경계
- 채널 간 출처 링크와 요약 권한
- AI 요약을 검증된 캔버스로 승격하는 흐름
- Nostr 이벤트 구조 또는 Rust 명령 변경
- 기존 SchoolX 데이터 마이그레이션 판단
- 보안 리뷰, 통합 테스트, 최종 코드 리뷰

## 새 세션을 시작할 경계

### 세션 A — 다국어 기반

범위:

- 번역 런타임
- 언어 저장과 전환
- 설정 및 첫 화면 적용
- 로케일 테스트

완료 조건:

- 타입 검사, 정적 검사, 단위 테스트, 프로덕션 빌드 통과
- 한국어와 영어 전환 후 새로고침해도 언어 유지

이 세션이 끝난 뒤 반복 번역은 낮은 추론 모델로 전환할 수 있다.

### 세션 B — 제품 설정과 브랜딩

새 고추론 세션으로 시작한다.

이유:

- 제품명 변경은 Tauri 설정, 번들 식별자, 딥링크, 저장 경로, 업데이트, 테스트에 동시에 영향을 준다.
- 기존 Buzz 설치의 데이터와 충돌하지 않는지 별도 검증해야 한다.

### 세션 C — SchoolX 워크스페이스 템플릿

새 고추론 세션으로 시작한다.

이유:

- 기존 Buzz 템플릿 적용 로직과 관리형 에이전트 재사용 규칙을 함께 다뤄야 한다.
- 재적용, 부분 실패, 기존 채널 충돌의 원자성과 사용자 복구 방법을 결정해야 한다.

최소 범위는 메인 회의방과 기획방 두 개다. 스키마와 적용 흐름이 안정되면 나머지 템플릿 데이터는 낮은 추론 모델로 확장할 수 있다.

### 세션 D — 코디네이터와 지식 승격

새 고추론 세션으로 시작한다.

이유:

- 비공개 채널 정보가 요약을 통해 유출되지 않도록 권한을 증명해야 한다.
- 원본 대화, AI 임시 요약, 검증된 캔버스의 상태 경계를 설계해야 한다.

### 세션 E — 파일럿 E2E와 패키징

새 고추론 세션으로 시작한다.

이유:

- 한글 IME, 권한, 딥링크, 설치 데이터 격리, Huddle을 하나의 사용자 여정으로 검증해야 한다.
- 여러 기능 세션의 결과를 통합 검토하는 단계다.

## 낮은 추론 모델에 전달할 작업 명세 형식

```text
목표:
  지정된 화면의 사용자 노출 문자열을 기존 i18n 패턴으로 전환한다.

허용 파일:
  <정확한 파일 또는 디렉터리>

반드시 유지:
  비즈니스 로직, 테스트 ID, Nostr/CLI/프로토콜 값, 영어 폴백

구현 규칙:
  기존 namespace와 키 네이밍을 따른다.
  번역되지 않은 동적 사용자 콘텐츠는 수정하지 않는다.
  한국어는 존댓말과 간결한 제품 문체를 사용한다.

완료 조건:
  타입 검사 통과
  정적 검사 통과
  해당 기능 테스트 통과
  영어·한국어 키 구조 일치
```

이 명세보다 넓은 판단이 필요해지면 낮은 추론 작업을 중단하고 고추론 세션으로 되돌린다.
