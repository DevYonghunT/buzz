# 문서 작성 스킬

## 왜 도구가 고정되어 있나

같은 학교 안에서 사람마다 다른 라이브러리로 문서를 만들면 결과물의 글꼴,
여백, 표 모양이 제각각이 된다. 문서 품질은 라이브러리가 아니라 **서식**이
결정하므로, 도구는 여기에 못박고 서식에 힘을 쓴다.

**새 라이브러리를 찾지 말 것.** 여기 적힌 것으로 안 되는 일이 생기면
§도구 선택 기록에 그 사실을 적고 사용자에게 알린다.

## 실행 환경 — `uv`

시스템 파이썬은 3.9라 아래 도구 대부분이 요구하는 3.10 이상을 만족하지
못한다. **항상 `uv`로 실행한다.** 시스템 파이썬을 건드리지 않고, 필요한
버전을 알아서 받아 격리된 환경에서 돌린다.

```bash
uv run --python 3.12 --with python-hwpx python script.py
```

`--with` 에 필요한 패키지를 나열한다. `pip install` 을 시스템에 직접 하지
않는다.

## 형식별 도구

| 형식 | 패키지 | 비고 |
|------|--------|------|
| HWPX | `python-hwpx` | 한글 프로그램 불필요. Apache-2.0 |
| DOCX | `python-docx` | |
| XLSX | `openpyxl` | |
| PPTX | `python-pptx` | 빈 슬라이드에서 시작하면 디자인이 매번 달라진다 — 템플릿을 강하게 권할 것 |
| PDF | `weasyprint` | HTML/CSS → PDF. 한국어 글꼴을 CSS에서 지정한다 |
| md → docx | `pandoc` | 이미 설치되어 있다. 빠른 변환에만 쓴다 |

PDF는 WeasyPrint가 시스템 라이브러리(pango, cairo)를 요구한다. 없으면
`brew install pango` 가 필요하니, 사용자에게 먼저 알리고 동의를 받는다.

## 서식(템플릿)이 먼저다

문서를 만들기 전에 **항상 `~/.schoolx/TEMPLATES/` 를 먼저 확인한다.**

```bash
ls ~/.schoolx/TEMPLATES/
```

- **맞는 서식이 있으면** 그것을 열어 내용만 채운다. 묻지 않는다.
- **없으면** 기본 서식으로 문서를 만들어 **먼저 결과를 준다.** 서식을
  달라고 요구하며 작업을 멈추지 않는다.

작업을 마친 뒤, 결과를 전달하면서 한 줄 덧붙인다:

> 이번에는 기본 서식으로 만들었습니다. 학교에서 쓰시는 양식 파일을
> `~/.schoolx/TEMPLATES/` 에 넣어 두시면 다음부터 그 서식 그대로 만들어
> 드립니다. (예: `가정통신문.hwpx`)

이 순서가 중요하다. 먼저 물으면 대부분 "그냥 만들어 줘"로 흘러가고 서식은
영영 생기지 않는다. **결과물을 본 직후**가 사용자가 서식을 넣을 마음이 드는
유일한 순간이다.

형식별로 한계를 구체적으로 말한다. 뭉뚱그리면 전달되지 않는다.

- **HWPX** — 표와 글은 잘 되지만 도형·이미지 처리가 제한적입니다. 로고나
  머리글이 들어간 양식은 서식 파일을 주시는 편이 확실합니다.
- **PPTX** — 빈 슬라이드에서 시작하면 색과 글꼴을 제가 임의로 정합니다.
  학교 테마가 든 파일을 주시면 그 디자인을 그대로 씁니다.
- **DOCX** — 제목·본문 스타일이 정의된 문서를 주시면 그 스타일로 씁니다.

## HWPX — 실제로 확인된 사용법

2026-08-07에 `python-hwpx` 6.0.2로 직접 만들어 한글에서 열리는 것까지
확인했다. 아래는 그때 확인된 내용이다.

### 새 문서

```python
from hwpx.document import HwpxDocument

doc = HwpxDocument.new()
doc.add_heading("2026학년도 여름방학 가정통신문", level=1)
doc.add_paragraph("학부모님께 드립니다.")

table = doc.add_table(rows=3, cols=2)
table.cell(0, 0).text = "구분"
table.cell(0, 1).text = "내용"

doc.save_to_path("가정통신문.hwpx")
```

### 서식 채우기 — 표가 있는 문서는 이 방법을 쓴다

```python
doc = HwpxDocument.open("~/.schoolx/TEMPLATES/가정통신문.hwpx")
doc.tables.fill_by_path({
    "개학일>right": "2027. 2. 2.(화)",
    "방학 기간>right": "2026.12.24. ~ 2027.2.1.",
})
doc.save_to_path("완성.hwpx")
```

경로는 **`라벨>방향`** 이고 구분자는 `>` 다. 방향은 `right` `left` `up`
`down`. 라벨 칸을 찾아 그 방향의 칸에 값을 넣는다. 학교 서식의 「항목 : 값」
구조에 그대로 맞는다.

어떤 라벨이 있는지 모를 때:

```python
doc.tables.map()                      # 표 전체 구조
doc.tables.find_cell_by_label("개학일")  # 라벨 위치와 대상 칸
```

### 반드시 지킬 것 세 가지

**1. 본문 치환은 표 안에 닿지 않는다.**
`doc.text.replace("개학일", ...)` 는 표 안의 글자에 대해 **0** 을 반환한다.
표는 반드시 `doc.tables.fill_by_path` 를 쓴다. 이걸 모르면 "치환했는데 안
바뀐다"로 오래 헤맨다.

**2. 6.0에서 옮겨간 이름을 쓴다.** 옛 이름은 7.0에서 사라진다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| `export_text()` | `text.plain()` |
| `replace_text_in_runs()` | `text.replace()` |

**3. 저장 후 반드시 검증한다.**

```python
report = HwpxDocument.open(out).validate()
assert not report.issues, report.issues
```

`doc.tables` 는 첨자로 접근할 수 없다(`doc.tables[0]` 은 오류). `all` `map`
`fill_by_path` `find_cell_by_label` `merge_cells` 를 쓴다.

## 결과 전달

만든 파일은 사용자가 찾을 수 있는 곳에 둔다. 바탕화면(`~/Desktop`)이
무난하다. `.scratch/` 는 사라질 수 있으므로 결과물을 두지 않는다.

파일을 만든 뒤에는 **경로를 정확히 알려준다.** 임시 폴더 경로만 말하면
사용자가 찾지 못한다.

## 도구 선택 기록

여기 적힌 도구로 해결되지 않는 일이 생기면, 새 도구를 찾기 전에 **먼저 이
절에 무엇이 막혔는지 적는다.** 그리고 사용자에게 알린다. 도구를 바꾸는 것은
사용자의 결정이지 에이전트의 판단이 아니다 — 사람마다 다른 도구를 쓰기
시작하면 이 스킬이 존재하는 이유가 사라진다.

| 날짜 | 형식 | 결정 | 근거 |
|------|------|------|------|
| 2026-08-07 | HWPX | `python-hwpx` 채택 | 한글 프로그램 없이 macOS에서 생성·서식 채우기·검증까지 확인. 한글에서 정상 표시 확인 |
| 2026-08-07 | HWPX | `pyhwpx` 제외 | 한글 프로그램이 설치된 Windows에서만 동작 |
| 2026-08-07 | 실행환경 | `uv` 고정 | 시스템 파이썬 3.9로는 요구 버전(3.10+)을 못 맞춤 |
